# 1920x440 超宽屏 UI 设计

## 目标
为 1920x440、11.3 寸触控屏适配 KlipperTouch，让 UI 优先利用横向空间，减少纵向堆叠，同时保持可靠的手指触控尺寸。

## 目标屏幕
目标布局是横屏 1920x440，内容区非常宽，但垂直高度有限。`Metrics.qml` 已经提供 `ultraWide` 判定：横屏、高度不超过 520、宽高比不低于 3.0。此次适配应继续基于这个现有入口。

扣除 `StatusBar` 后，可用高度大约只适合三行紧凑内容。各面板应避免需要用户阅读或点击大量纵向堆叠行的布局。

## 布局方向
采用已确认的均衡三栏方向：

1. 左栏：主要操作控件。
2. 中栏：状态、图表、预览或空间可视化。
3. 右栏：次要控件、参数、确认区或紧凑详情。

只有当内容天然适合表格化展示，并且每个触控目标仍能保持足够尺寸时，面板才可以使用四栏。文件元数据、打印指标、风扇和系统列表可以考虑四栏；运动控制和高风险操作不应使用四栏。

## 触控规则
超宽布局必须保证手指操作可用：

- 普通可点击控件高度应至少为 48 px。
- 运动、挤出、加热、打印控制以及接近重启语义的控件，应以至少 56 px 为目标。
- 破坏性或高风险操作必须保留现有确认流程，并且视觉权重要大于相邻的取消或关闭操作。
- 数字 chip 可以更紧凑，但较短轴的点击区域至少应为 44 px。

文字必须在固定高度控件内省略或换行，不能通过撑高行来解决。超宽布局不应依赖随视口宽度增长的字体缩放。

## 面板要求

### Shell
`BaseShell.qml` 在超宽模式下继续保留当前左侧 `ActionBar` 和顶部 `StatusBar`。`ActionBar` 不应按 1920 px 屏幕的 10% 继续变宽，因为这会浪费横向空间；它应使用有上限的宽度，同时保持四个足够大的纵向按钮。

`Metrics.qml` 应提供可复用的超宽尺寸，例如有上限的 action bar 宽度、最小触控尺寸、安全触控尺寸、紧凑行高和面板列间距。

### Main Menu
主菜单应保留温度摘要，但避免高纵向菜单栈。超宽模式下，温度摘要和菜单 tile 应并排放置。菜单 tile 应增加列数，让当前五个入口在两行或更少行数内显示。

### Temperature
温度面板在超宽模式下应使用三个横向区域：图表、设备卡片、目标温度控制或紧凑设备操作。图表应保持可见，但不能占用过多宽度导致控制区变窄。当存在 2 到 4 个温度设备时，设备控制应尽量避免分页。

### Move
移动面板已经有部分超宽行为，应收紧而不是重写。主页面应在一屏内放下 XY 控制、Z 控制、动作控制、位置反馈以及距离/速度选择。床调平可以在较小布局中继续作为详情页，但在超宽模式且五轴控制可用时，可以和主移动控制并排显示。

运动控制必须使用更安全的触控目标尺寸。被禁用或不可用的运动命令应继续保持明显的禁用状态，并复用现有 guard 文案。

### Extrude
挤出面板应在一个超宽页面内显示喷嘴温度、Pressure Advance、耗材传感器状态、进料设置和挤出动作。长度和速度选择应以横向或两行 chip 组展示，而不是纵向列表。Load/Unload 和材料系统控制应作为 Extrude/Retract 的次要操作。

挤出操作必须继续遵守现有 ready 和 can-extrude guard。

### Files
文件面板应利用横向空间减少模式切换。超宽模式下，文件列表应保持可见，同时选中文件详情显示在右侧详情栏。选择文件不应在 1920x440 下强制进入全页详情视图。

文件行应紧凑但仍易于点击。元数据应分组为小型区块，预览缩略图和文件动作放在详情栏内。

### Job Status
打印状态页应采用大方、极简的设计，不应做成信息密集的仪表盘。超宽模式的主页面只展示最重要的打印信息：

- 当前层 / 总层数
- 估算剩余时间
- 已打印时间

速度倍率、挤出倍率、Z offset、坐标、加速度、速度、文件元数据和对象详情等次级信息，不应出现在超宽 Job Status 主页面上，除非用户主动进入详情视图。

打印控制按钮应采用类似音乐播放器的无文字图标控制组。按钮依赖熟悉图标表达含义，例如 pause、resume、cancel、skip 和 clear，而不是显示文字标签。触控目标仍必须足够大，高风险动作仍应保留确认流程。

Pause/Resume、Cancel、Skip Object 和 Clear 行为必须保留当前 staged 或 confirmed action 流程。

### More、Fans、Info、Notifications、Placeholders
次级列表页面在超宽模式下应优先使用 3 到 4 列，避免很长的纵向堆叠。风扇卡片、系统状态行、通知项和占位菜单入口应使用固定触控高度的紧凑卡片。

## 安全边界
本工作只做布局适配。不得新增运动、加热、挤出、打印控制、重启或原始 G-code 命令。现有命令 guard 和默认只读行为必须保持有效。

## 测试与验证
为超宽 metrics 和各面板的布局入口添加 QML 结构测试。现有测试应继续验证响应式方向行为。

使用截图工具至少捕获以下尺寸：

- `1920x440`
- `800x480`
- `1024x600`
- `480x800`

1920x440 截图需要检查：

- 文本和控件没有重叠
- 主面板不需要超过三行纵向控制
- Job Status 主视图只展示层数、剩余时间、已打印时间和播放器式图标控制
- 触控目标符合上面的最小尺寸要求
- 左侧 action bar 和顶部 status bar 仍然可用
- 详情较多的面板利用横向空间，而不是强制全页钻取

实现完成前运行 `pytest`、`ruff`、`mypy` 和 `git diff --check`。

## 不在范围内
本设计不实现新的 KlipperScreen 面板、不新增命令能力、不新增主题美术，也不改变真实打印机行为。它也不会替换现有竖屏或 800x480 行为；这些布局必须继续可用。
